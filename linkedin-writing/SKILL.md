# LinkedIn Writing

> Write LinkedIn articles/posts in Athalla's voice — conversational tech storytelling in Indonesian-English mixed style.

## Trigger
The user will say things like:
- "Help me write a LinkedIn post about [topic]"
- "Draft a LinkedIn article for [my project/workflow/tool]"
- "Turn this into a LinkedIn post"

## Voice & Tone

### Language
- **Primary:** Casual Indonesian, mixed with English tech terms naturally (no forced translation)
- **English terms preserved:** research, agent, orchestrator, use case, debugging, scope, context, workflow, issue, etc.
- **Tone:** Explaining to a fellow engineer over coffee — informal, relatable, slightly self-deprecating

### Personality Markers
- Use conversational fillers naturally: "sebenarnya," "singkatnya," "kira-kira," "ternyata"
- Self-awareness / humor: "haha," "😅" (sparingly, 1-2 per post max)
- "cmiiw" when speculating or not 100% sure
- "oh iya," as a natural transition to an additional point
- "Hopefully..." in closing for modest, non-preachy endings

## Structure Pattern

Every post follows this arc:

### 1. Hook — Relatable Pain Point (1-3 sentences)
Start with a problem the reader has probably experienced. Make it specific and personal.
```
"Semakin sering baca forum, semakin banyak nemuin repo github yang menarik buat diulik."
"Belakangan ini sering delegate task ke AI, apalagi pas iseng bikin project fullstack end-to-end."
```

### 2. The "Akhirnya" Pivot
Transition into the solution with a natural pivot phrase:
```
"Akhirnya kepikiran bikin tools simpel buat..."
"Akhirnya nemu workflow personal yang cocok..."
```

### 3. Solution / Walkthrough
- Keep it concrete — show the actual flow, code, or file structure
- Use numbered lists for workflows
- Use code blocks for file trees, commands, or structured data
- Mix technical detail with "why" reasoning

### 4. Findings / Tips / Closing Reflection
- Bullet-pointed takeaways (numbered or bullet list)
- Broader lesson or unexpected discovery
- Close modestly with "Semoga membantu" or "Hopefully..."

## Formatting Rules

- **Bold** for key terms on first mention
- Numbered lists for sequential flows
- Bullet lists for findings/tips
- Code blocks for file trees, JSON, commands
- No headings inside the post body (the hook IS the opening, no "## Introduction")
- Single `#` only for the post title (or no heading at all if the hook is strong enough)

## Content Rules

- **Always rooted in personal experience** — never write generic advice. Start with something YOU built, tried, or discovered
- **Practical over theoretical** — show real code, real commands, real file structures
- **One core idea per post** — don't cram multiple topics
- **No clickbait or hype** — understated, honest, "here's what I found"
- **No corporate speak** — no "leveraging synergies" or "driving innovation"
- **Length:** Aim for the samples' range — roughly 20-60 lines. Long enough to be substantive, short enough to read in 2-3 minutes

## Before Writing

Read at least 2-3 sample posts from `samples/` to calibrate on voice, rhythm, and density.
